表格提供起点，用户明确指定的方法优先。方法选择同时受资料门槛约束：方法擅长的维度与现有资料不匹配时，保留指定方法可用部分，并把需要补充的资料和会改变的层级写进问题卡。

## 主法与辅法职责

一个子问题先指定一个主法：主法承载该子问题的主要结论、取用链和时间解释。辅法只承担清楚的补充维度，例如：

- 八字/紫微/星盘负责个人长期结构，奇门或六爻负责一个具体窗口；
- 六爻负责当前成败与应期，奇门补方位和主客动静，大六壬补多方传递；
- 八宅、玄空分别记录居者适配和宅运理气，形势与实际动线作为现实核验；
- 塔罗提供牌阵叙事，雷诺曼提供事件语法，灵签提供签谱与典故，三者各守材料边界；
- 五运六气、太乙、皇极经世负责不同尺度的宏观时间框架，现实气候或历史事实单独核验。

辅法的结论与主法发生差异时，先检查主体、时间尺度、证据层和取用对象，再按条件分支输出。方法之间建立职责映射，不以数量或表决合并结论。

## 复合问题拆分

把包含多个动词或多个时间跨度的问题拆成子问题，并为每项写出“主体—事项—范围—主法—辅法”：

| 复合表达                             | 子问题示例                             | 主法安排                                     |
| ------------------------------------ | -------------------------------------- | -------------------------------------------- |
| “未来两年换城创业能否成功、哪月动身” | 个人承载与阶段；创业事件；迁移日期     | 八字/紫微；六爻或奇门；黄历/奇门择时         |
| “我和伴侣会不会结婚，什么时候谈成”   | 关系结构；当前谈判；时间窗口           | 双盘；六爻/大六壬；双方运限叠加              |
| “这套房适不适合我，何时装修”         | 居者与宅的长期适配；空间现状；施工择日 | 住宅合参；形势与现场；黄历/奇门              |
| “这个病能否治好”                     | 现实健康事实；术数仅作象意与时间叙事   | 专业资料为主；相关术式只作个人感受与阶段记录 |
| “签文和八字都看事业”                 | 签谱题意；本命长期承载；当前机会       | 灵签与八字分别判断，再说明交集与分歧         |

拆分后的子问题共享已确认主体和时空资料，独立建立证据账；如果某项需要新起卦或新抽牌，明确它是新的占问时点。

## 路由决策树

1. 先看用户是否明确指定术式；有指定时保留其身份，按资料门槛确定可用层级。
2. 再看主体是个人、双方、单一事件、房屋、日期、年度还是原典资料。
3. 再看时间是本命、阶段、年度、近期窗口还是一个起盘时点。
4. 选择与主体和跨度都匹配的规范身份，确定主法；需要的补充维度再选辅法。
5. 检查最小资料：起盘类核验起盘时刻与动变，出生类核验时刻地点，择日类核验候选范围，宅居类核验坐向与宅龄，牌签类核验原始牌签资料。
6. 读取 `reading-workflow.json` 对应条目的 `whenToRead`、`inputs`、`scope` 和 `guide`，再按需打开方法 reference。
7. 在问题卡中写下“选用理由、暂未使用的方法、缺项影响”，供合参与最终复核使用。

## 路由结果契约

路由完成时形成一行结构化记录：

```text
主体：……；核心事项：……；时间范围：……；主法：……；辅法：……；
已具备资料：……；待补资料：……；主法回答：……；辅法回答：……。
```

这行记录只服务于内部组织，交给在线 AI 时把它展开为自然语言问题、盘面资料、传统依据和输出要求，不把规范 key 或内部路由说明写进提示词正文。
